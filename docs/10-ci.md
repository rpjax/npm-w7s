# Using w7s in CI

w7s is designed so that the parts which need no container can run in any runner, and the
parts which do fail loudly instead of degrading.

## What runs without a workshop

```yaml
- uses: actions/checkout@v4
- uses: actions/setup-node@v4
  with:
    node-version: 22
- run: npx @rodrigopjax/w7s gecko validate --offline --json
```

`validate --offline` checks the manifest against the schema, the graft tree against the
manifest, and `graft.lock.json` against both — with no clone, no Docker and no network. It
is the check that belongs on every pull request touching `gecko-engine/`.

`lock --check` belongs beside it: it fails when the lock is stale relative to the graft, so
a change to `graft/` that forgets to regenerate the lock cannot merge.

```yaml
- run: npx @rodrigopjax/w7s gecko lock --check --json
```

## What needs a workshop

`init`, `build`, `artifact`, `run` and `shell` need a container engine and enough memory.
On a runner that has neither, they exit 4 with a message naming what is missing — they do
not fall back to a partial result.

A cold Gecko build is roughly 1h40 and 19.6 GB peak, so a hosted runner is the wrong place
for it. The realistic arrangement is a self-hosted runner or a nightly job producing the
payload, with `dist --pull` retrieving it elsewhere:

```yaml
- run: npx @rodrigopjax/w7s gecko dist --pull ${{ github.sha }} --verify
```

## Parsing results

Every verb accepts `--json` and guarantees a single JSON document on stdout.

```bash
w7s gecko validate --offline --json | jq -e '.ok'
w7s gecko status --json | jq -r '.report.stages[] | select(.stale) | .id'
```

Branch on exit codes when the distinction matters:

| code | in CI, usually means |
|---|---|
| 2 | the manifest is wrong — fail the build |
| 3 | someone committed a workspace edit that never reached `graft/` — fail |
| 4 | this runner cannot do this step — skip it, do not retry |
| 5 | a stage is behind; with `--check` this is the staleness gate |
| 6 | an invariant broke — fail, and read the message |
| 7 | a declared suite went red |

## Gating a deploy

dockup's `prepare` hook is the integration point, so the gate lives in the deploy manifest
rather than in a workflow step:

```jsonc
{ "id": "sidecar", "prepare": ["w7s gecko ship --to dist"] }
```

A non-zero exit aborts the deploy. See [06-provider.md](06-provider.md).
